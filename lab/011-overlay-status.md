# 设计记录 011：翻译悬浮窗与实时状态

日期：2026-10-23 · 触发：lab/010 讨论中确认"状态展示放在桌面窗口里用户看不到（游戏前台全屏）"，需要可开关的悬浮窗。本文档是实施期间的决策依据。

## 背景与动机

- 翻译逐条按需进行，不存在总量，不能做 0–100% 进度条（lab/010）
- 用户需要区分三种状态：**正在翻译 / 已缓存命中 / 失败重试**，失败开放返回原文时尤其容易误读为"没翻译"
- Franca 是桌面 WPF 应用，无游戏内绘制能力（游戏内绘制属 Loader 实验路线，不依赖）

## 决策记录（均已确认）

1. **自写 WPF 悬浮窗，不引入第三方库**：`Topmost` + `AllowsTransparency` 透明背景 + 点击穿透（`WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`，不抢焦点、不吃游戏按键）的无边框小窗，核心代码约五十行，直接复用现有 UiStrings 多语言体系
   - [GameOverlay.Net](https://github.com/michel-pi/GameOverlay.Net) / [Overlay.NET](https://github.com/lolp1/Overlay.NET) 仅作窗口定位参考（均停更，且为游戏内绘制场景设计）；引入反而背负 SharpDX 时代依赖
2. **可开关**：设置项持久化；默认关
3. **硬限制写进文档**：独占全屏的游戏看不到悬浮窗；无边框/窗口化模式可进行测试，但仍需验证实际叠加和交互。该窗口不注入游戏进程，不代表反作弊或账号安全保证
4. **展示内容**（状态指示，非进度条）：
   - 当前模式（高速/质量）
   - 本次会话已处理 N 条 · 缓存命中率 M%
   - 在途 K 条 · 失败重试 X 条（在途/失败计数器为 RelayServer 新增；ServedCount/CacheHits/HitRate 已有，RelayServer.cs:46-48）
   - 状态语义：在途>0 → 等一等；失败在涨 → 端点问题，提示查健康状态；数字不动 → 可能没指向中继，提示跑诊断
5. **与其他功能的关系**：独立任务，与 lab/010 并行；计数器由 lab/010 的 RelayServer 改造一并提供，悬浮窗只做展示

## 涉及代码（预估）

- 新增悬浮窗 Window（Views/OverlayWindow.xaml）：穿透、置顶、跟随/固定位置、可拖动
- `RelayServer` 计数器（与 lab/010 同改）：在途数、失败数
- `AppSettings`：悬浮窗开关 + 位置记忆
- 设置页入口；游戏运行时悬浮窗自动显示该游戏状态（依赖 GameRuntimeMonitor 的运行时归属）
- 仅 RelayServer 运行时（有游戏在翻）才显示计数，避免展示陈旧数据

## 验证要求

- 构建零警告零错误
- 悬浮窗在游戏前台时**不抢焦点、不吞键盘输入**（重点验证）
- 多 DPI 缩放渲染正常；位置记忆跨重启生效
- 开关持久化；中继停止时悬浮窗隐藏或显示"未运行"
- 不注入、不修改任何游戏文件；真实游戏验证用无边框模式
