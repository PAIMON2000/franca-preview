# 014 UE 静态翻译适配器（pak 覆盖路线）立项

2026-10-25。路线决策：东方（ZUN）之后下一引擎做 **UE**（Godot 暂缓，理由见下文）。本文为执行计划与格式依据；侦察证据在本地忽略目录 `tools/ue-pak-recon/`（Node 原型脚本 + Npc 中英对照 JSON）。

## 为什么是 UE 不是 Godot

- 目标游戏索引未加密、Zlib、单游戏 pak，文本是标准 locres（en/zh-Hans/zh-Hant 三语官方，游戏表约 7.3 万条英文）。官方译文可作对照；分组数量与跨语额外键以本文后面的实现核对为准，早期“所有 key 完全一致”的推断已更正。
- Godot 代表靶 StS2：1.8G pck + 二进制 .translation + 像素字体几乎必撞字形墙（东方静态路线已被证伪的同一坑，见 lab/013）；无成熟运行时注入生态。Turing Complete 明文翻译不具代表性。
- 排除项：八方旅人 2 无游戏 locres（SE 私有格式）；黑神话页脚自定义/混淆；P3R 索引加密（二期再评估）。

## 路线形态

**纯静态 pak 覆盖**：解析原 pak → 抽取源 locres → 翻译 → 序列化目标 locres → 游戏外准备 `pakchunk99-WindowsNoEditor_P.pak`，后续真机阶段才放入 `Content/Paks`。原 pak 字节不动；拟定停用/卸载 = 移除覆盖 pak。无运行时注入、无游戏进程依赖；挂载优先级仍须目标游戏实测。

第一版拟**覆盖 zh-Hans 槽位**（游戏内语言切简中显示机翻译文）：复用官方简中字体，实际字形覆盖与加载效果仍待真机验证；现场可与官方译文对比（摘掉覆盖 pak 即官方）。备选形态（覆盖 en 槽位做演示）后续按需。

已知限制（先写清）：
- UE 启动时一次加载全部 locres，**新增/更新译文需重启生效**（无 thcrap 式热更新）。
- 若游戏启用 pak 签名校验，覆盖 pak 需另处理（侦察未见签名痕迹，真机验证时确认）。
- 全量 73k 条耗时尚无实测，原先 2.5~3 小时及首批约 40 分钟为未经验证的估算，不作交付承诺；分批：①系统/Npc/Skills技能表/Buff与道具/门派地图与提示，加程序导出/坐骑 16,506 条 ②Quests任务表 17,816 条 ③CG表 38,711 条。

## 格式依据（侦察实证，全部只读验证过）

pak v11（UE4.26-5.x，repak 兼容性表 v11=Fnv64BugFix）：
- **页脚在文件尾**：`[16 字节 uuid][1 字节索引加密标志] magic(0x5A6F12E1) u32主版本 u64索引偏移 u64索引大小 20字节SHA1 [5×32字节压缩名]`。magic 前 17 字节极易误读，解析时以"从尾向前找 magic"定位。
- **索引头**：mountPoint FString → u32记录数 → u64 pathHashSeed → u32 hasPhi(+u64偏移/u64大小/20字节哈希) → u32 hasFdi(同) → u32编码条目区大小 → 编码条目区 → u32非编码条目数 → 非编码条目。phi/fdi 偏移为**绝对文件偏移**，落在索引区之后。
- **FDI（目录清单）**：u32目录数 → 每目录：FString 目录名、u32文件数、每文件 FString 文件名、i32 编码偏移。**文件名可为 UTF-16**（中文资产名，如 `Boss战.uasset`）；FString 负长度 = UTF-16，磁盘占用 = (-len)×2 字节（含终止符）。
- **编码条目（12 字节起）**：u32 bits → 压缩槽(bits>>23&0x3f，0=无)、加密位(bit22)、块数(bits>>6&0xffff)、块大小(bits&0x3f，0x3f 则后跟 u32，否则 ×0x800)；bit31/30/29 分别控制 offset/uncompressed/compressed 为 u32 还是 u64；压缩且块数>1 时后跟每块 u32 尺寸。
- **数据区**：条目偏移处是完整条目头（u64偏移 u64压缩尺寸 u64原始尺寸 u32压缩槽 20字节哈希 [u32块数+块(u64,u64)] u8标志 u32块大小），其后是数据。**压缩块偏移相对条目起始**；v11 块为 (start,end) 对。Zlib 按块解压（实测压缩槽声明与内容可能不一致，按块魔数 78 xx 探测最稳）。
- 覆盖 pak 需自造索引：phi 需要 fnv64（lower-case UTF-16 路径 + 种子，种子明文存索引头可自选）；fdi 按上格式；两者 SHA1 写入索引头。

locres v3（Optimized_CityHash64_UTF16）：
- **魔数 16 字节 GUID**：`0e147475 674a03fc 4a15909d c3377f1b`（0x7574140E...小端）。旧文档的 4 字节魔数不适用。
- u8 版本（1=Compact 字符串 LUT，2=Optimized_CRC32，3=Optimized_CityHash64_UTF16）。实测 v3。
- v≥1：i64 字符串 LUT 绝对文件偏移（-1=无）→ LUT：u32 条数 → 每条 FString + （v≥2: i32 引用计数）。
- v≥2：跳过 u32 EntriesCount；u32 命名空间数 → 每空间：u32 哈希 + FString 名 + u32 key 数 → 每 key：u32 哈希 + FString key + u32 SourceStringHash + i32 字符串 LUT 索引。
- 改写策略：命名空间/key 不动则其哈希不动；只改 LUT 字符串内容与索引，SourceStringHash 保留原值（避免触发源文变更回退）。

## 阶段与验收门槛

1. **格式库 + 合成 pak 探针**（本阶段）：C# 实现 pak 读/写 + locres 读/写；`--probe-ue-pak` 用临时目录合成 pak（含 UTF-16 名、多压缩块、locres 打桩）做 写→读→回读 断言。构建 0 警告，architecture/blueprint 探针过。
2. **翻译接入**：UeStaticService / StaticTextTranslationService 复用既有提供者和 PackStore（每游戏缓存、LLM 批量至多 20 条且每请求至多 200、熔断续译、片段进度），准备流程=抽源 locres→译→游戏外生成覆盖 pak；阶段产出=第 1 批译文缓存。探针 `--probe-ue-static` 全合成夹具；不接正式 enable。
3. **真机验收**（验收时在场）：只读判定→（授权后）放置覆盖 pak→窗口化静音启动→简中画面与官方译文对照→停用=删包还原。失败不留半成品。

## 边界

### 2026-10-25 实现核对后的格式修正

- PHI 哈希输入为**挂载点相对路径**的小写 UTF-16LE，初值 `0xcbf29ce484222325 + seed`；PHI/FDI 中的编码偏移相对编码条目 blob 起点。主索引的大小与 SHA1 不包括随后 PHI/FDI。PHI 末尾有空目录索引计数。
- 压缩方法索引 1 对应页脚第 0 个槽位；条目 SHA1 对应磁盘压缩数据；数据区头偏移为零。单块条目的块大小等于原始尺寸，索引短位域可省略为零。
- locres v3 键哈希总是基于 UTF-16LE CityHash64，再按 `low32 + high32 * 23` 折叠；SourceStringHash 是独立的 UE StrCrc32，改译文时原值（包括零）不变。
- 真实游戏英文是 **9 张游戏表、73,033 条**；另有 4 组引擎/插件资源。只有 Npc/CG/坐骑/门派地图等表已核对键集合相等，Buff/Quests/Skills/程序导出/系统的简中分别多 119/7/3/8/19 条，不能再声称所有语言键集合完全一致。准备时保留目标独有条目，并拒绝源键缺失或源文哈希不一致。
- 当前仅游戏外准备；CLI `--ue-inspect` 只读，`--ue-prepare` 限 Google Translate 与 Bing，仍尊重停用选择；`--ue-prepare-cached` 禁用所有端点，仅用已有缓存。探针不调用真实服务。

- 本阶段游戏目录**零写入**；原 pak 只读；探针只用临时目录与合成数据，不联网。
- 上述零写入限定准备服务与合成探针；随后单独授权的真实放包/启动记录见本轮测试。UE4.26.2 首轮压缩覆盖包解压失败，准备服务已改为不压缩；不压缩中文包能进入地图加载并正常退出，画面仍未经独立确认。为区分官方简中，后续日语菜单验证使用 `--language=ja --slot=zh-Hans`，缓存语言独立，游戏内仍选择简中槽位。
- 翻译经现有端点管线（免费池），遵守熔断与逐条缓存；不直连端点写一次性脚本。
- 对外表述：UE 适配未完成真机验收前不得写"已支持"。
