# 设计记录 010：内置词典与高速/质量双模式

日期：2026-10-23 · 触发：用户提出翻译进度可视性与翻译效率问题，经多轮讨论收敛为以下设计。本文档是实施期间的决策依据，避免上下文丢失。

## 背景与动机

- 新游戏首屏翻译延迟 5~6 秒（lab/001 实测）：每条 UI 文本首次遇到都走在线端点，通用词汇（Save/Settings/Inventory…）也反复走网络
- 用户看到新页面不是目标语言时分不清三种状态：正在翻译 / 已缓存 / 翻译失败（失败开放返回原文）
- 翻译是逐条按需的，**不存在"总量"概念，禁止做 0–100% 进度条**（假精度）

讨论过四档模式（离线高速 / 离线增强 / 在线高速 / 质量），最终收窄为两档，其余进路线图。

## 决策记录（均已确认）

1. **只做两个模式**：高速模式、质量模式。离线档仅列路线图；Qwen 本地模型档已随本地模型功能于 2026-10-24 移除。
2. **词典自建，不引外部词库**：
   - LunaTranslator 是 GPLv3，Franca 是 MIT：只作设计参考，不拿代码和数据（独立数据文件聚合分发的方案放弃，数据本身多为转载第三方、授权链不清，且为日→中，与英→中 UI 场景错位）
   - 商业工具（欧路/有道）词库不可提取再分发
   - 青简是 Rust 拼音输入法，词库为中→外词级学习词典，形态不匹配
3. **Firefox l10n 为可选种子加速**：Firefox 界面本地化数据（菜单/按钮/设置项的 en→zh 翻译，MPL-2.0）可脚本提取高频 UI 短语作为种子表，署名 + 独立数据文件聚合分发。可选，非必须；手工整理几百条为默认路径。
4. **种子仅英→中，作为技术验证**（15 种目标语言全做种子工作量过大）：词典存储按语言对设计（如 `dictionaries/<from>-<to>.json`），查找链、沉淀机制对所有语言对生效；其他语言对初期靠沉淀增长，功能不受影响，只是首屏无秒翻。UI 界面文案的 15 语言翻译走既有 UiStrings 体系，与词典无关。
   - **路线图（用户明确要求）**：技术验证通过后，每种支持语言都应内置一个**最小词库**（哪怕几百条），否则该语言用户首次使用完全体验不到高速模式。
4. **词典全局、跨游戏、随使用膨胀**；包缓存维持每游戏独立，职责为：游戏专属内容（人名、台词）的持久层 + XUnity 译文目录同步的来源。
5. **沉淀策略**：仅**短文本（≤30 字符）**在线翻译成功后自动沉淀进词典；长文本不自动沉淀；当前仅按长度筛选，没有人名或语境识别，短字符串也可能存在歧义和跨游戏误用。
6. **高速模式查找链**：词典 → 包缓存 → 在线。
   - 词典命中**立即返回**，同时对该文本发**后台在线请求**（不阻塞响应）；在线结果回来后走运行时重载升级（见下节）
   - 已确认接受：词典词条不被在线结果反复升级，升级只发生在词条首次沉淀时；词典命中是"第一次在线翻译的结果固化"
   - 词典优先级高于包缓存：同文本两边都有时以词典为准（全游戏一致性目标），文档需写明
   - "生成后不再优化"选项：勾选后词典命中直接结束，不发后台请求，仅停用此类后台升级，不保证文本覆盖
7. **质量模式**：不用词典，包缓存 → 在线。即现状行为，逐条到达逐条显示，无需重刷机制。
8. **UI 中途质量变化为预期行为**（词典机翻先显示、在线译文后到后升级），高速模式文档要告诉用户这一点。

## 技术机制：运行时重载升级（实施前必须先验证）

依据（TranslationInstaller.cs 配置模板，XUnity.AutoTranslator 5.6.2）：

- `Directory=Translation\{Lang}\Text`（:321）——XUnity 加载该目录下**所有** txt 作为静态译文
- `OutputFile=...\_AutoGeneratedTranslations.txt`（:322）——XUnity 把每条 200 响应持久化到这里，此后**不再重请求**该文本（同会话内靠端点重发无法升级已译文文本）
- `ReloadTranslationsOnFileChange=False`（:380）——原生支持监视译文目录、文件变更后运行时重载，需改为 `True`

升级链路（高速模式，未勾选"生成后不再优化"）：

```
词典命中 → 立即返回游戏 → 后台在线请求
        → 结果写入包 + 追加游戏译文目录 Translation\<lang>\Text\Franca.txt
        → XUnity 文件监视触发重载 → 该文本 UI 升级为在线译文
```

备选：若重载验证不可靠，升级退回"下次启动生效"（启动前把包+词典同步进译文目录，包→目录同步照做，功能不阻塞）。

## 实施前必须验证（探针优先）——已验证（2026-10-23，Suzerain 真实游戏，详见 `tests/2026-10-23-reload-probe.md`）

1. **重载优先级**：✅ 可行——独立 `Franca.txt` 稳定胜过 `_AutoGeneratedTranslations.txt`（双向验证），升级只写独立 txt，不改写 XUnity 缓存，避开运行时写竞争；注意 XUnity 对缓存文件是追加式写入，不重整理。
2. **Reload 风暴**：✅ 可行（注意事项）——单次写 50 条与 300ms 间隔连写 10 次均无可见卡顿/风暴；但 XUnity 不输出重载日志，重载次数只能按 UI 行为推断，写入仍按合并/节流实现。
3. **重载性能**：Suzerain 当次测试观察到约 1–2 秒内重载，273 条规模未观察到明显停顿；未测帧时间，也不保证其他游戏或后续版本的延迟。

验证过程排障记录：Steam 半连接（VersionMismatch）会卡死主菜单加载，与翻译配置无关；离线弹窗需人工/脚本点"仍然进行游戏"；本机 DPI 150%，无人值守点击须先 SetProcessDPIAware。

## 涉及代码（预估）

- 新增词典服务：全局存储（建议 `dictionaries/<lang>.json`），大小写/空白归一化后的哈希查找，内置种子 + 沉淀追加；词典条目带 `builtin/promoted` 来源标记
- `RelayServer`：查找链改造（词典层）、后台升级请求（fire-and-forget，需防重入——同一文本在途时去重）、新增计数器（在途数、失败数，供悬浮窗用）
- `TranslationInstaller`：模板 `ReloadTranslationsOnFileChange=True`
- 新增译文目录同步：游戏启动前把 包条目 + 词典条目 写成游戏目录 `Translation\<lang>\Text\Franca.txt`（需处理与 XUnity 缓存文件的优先级）
- `AppSettings`：翻译模式字段（高速/质量）+ "生成后不再优化"开关；设置页与游戏页 UI 文案（15 语言）
- `PackStore`/词典沉降：在线成功且短文本 → 写词典 + 写包
