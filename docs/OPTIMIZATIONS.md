## 待实现：全局 Auto 翻译模式

目标：玩家开启一个 Auto 开关后，直接从 Steam 玩游戏，无需逐个打开 Franca 游戏行的翻译开关。

当前行为：已启用的游戏保留翻译组件，之后启动时会尝试加载，无需每次勾选；实际加载与显示仍需逐游戏验证；走本地中继时仍需 Franca 在运行。尚未安装或被手动停用的游戏不会自动部署/恢复。

### 需要解决的机制

1. **首次部署必须赶在游戏启动之前。** 当前 `TranslationInstaller.EnableAsync` 是向游戏目录部署 BepInEx / XUnity 并写配置，不具备对已运行游戏热注入的能力。仅在进程出现后下载安装，不能保证本次启动就有翻译。[BepInEx 安装说明](https://docs.bepinex.dev/articles/user_guide/installation/index.html) 同样采用先部署到游戏目录、再运行游戏的方式。
2. **预部署范围和手动例外。** Auto 开关启用前说明将准备哪些兼容游戏；仅对已确认符合条件的游戏排队。跳过语言支持未知、兼容性未知和正在运行的游戏。手动停用应优先于全局 Auto，不能后台反复重新启用。
3. **与 Steam 启动方式配合。** 推荐先完成兼容游戏预部署，再监测实际启动；新装游戏在下一次游戏启动前准备。若首次准备未赶上，提示下次启动生效，不能静默重启玩家的游戏。
4. **配置更新要可逆。** 现有安装器遇到已部署环境/已有 INI 会保留原配置。Auto 需合并更新托管的源/目标语言与端点配置，保留玩家自己的配置并可回滚；避免游戏运行时写入加载器文件。
5. **运行进程与 App ID 精确匹配。** 现有错误监控只筛选已启用的 Unity 游戏、匹配根目录 exe，并跳过监控启动前已运行的进程。Auto 需另外支持实际游戏 exe、启动器及子目录，不能只匹配进程名。
6. **多游戏中继隔离。** 2026-10-22 已实现 `/translate/{appid}` 路由、实例化包缓存和单次请求配置快照；旧无身份请求继续翻译但不归档，不再使用 `ActiveGameAppId`。新安装/显式配置修复写入新路由。合成隔离验证见 `tests/2026-10-22-architecture.md`；两款真实游戏并行运行及旧配置迁移仍待验收，完整 Auto 仍依赖启动前准备与可恢复安装。

### 实施顺序与验收

- 第一阶段：明确 Auto 配置、兼容性范围及手动排除项；完成可取消的预部署队列、失败重试和回滚，不自动重启游戏。
- 第二阶段：进程与 App ID 映射、每游戏中继路由和配置刷新；与已知错误监控串联。
- 验收覆盖：一个未部署的测试游戏完整准备流程、从 Steam 正常启动、玩家手动停用、游戏已在运行、新装游戏、切换目标语言、两游戏同时请求、下载失败和 Franca 重启。

本轮将 Auto 作为优化项记录，未提供尚不能兑现上述行为的 UI 开关，也未批量修改任何真实游戏目录。
