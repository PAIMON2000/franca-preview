## 一、项目是什么

Windows 游戏翻译桌面原型，免费开源、非商业。当前能力范围见 `docs/site/index.html` 和 `docs/COMPATIBILITY.md`；社区服务与 Steam／工坊集成未实现。

以下为历史运行与排障经验；项目仍处原型验收阶段，不以早期“阶段过关”表述替代具体测试。

## 三、如何跑起来（新机器）

1. 安装 .NET SDK 9（`dotnet --version` 确认）。
2. `git clone` 仓库并进入目录。
3. `dotnet build src/Franca/Franca.csproj -c Release`。
4. 运行 `src/Franca/bin/Release/net9.0-windows/Franca.exe`。
5. 应用会扫描本机 Steam 库、标记引擎、后台补译名列并自动测速端点。

**注意**：对任一 Unity 游戏点「启用翻译」会自动安装 BepInEx / XUnity.AutoTranslator。东方 Project 路线首次启用时需要联网从上游镜像下载补丁数据（约 1 MB，逐个校验哈希）。安装会改动游戏目录，操作前先保留备份。

## 四、已实现能力（历史验证点）

当前能力与逐游戏证据以 `docs/DEVELOPMENT-PROGRESS.md`、`docs/COMPATIBILITY.md` 为准；下列为早期验证过的部件：

- Steam 库扫描：读注册表 + 解析 `libraryfolders.vdf` + `appmanifest` 清单。
- 引擎识别：声明式文件签名，覆盖 Unity IL2CPP / Mono、东方 ZUN 系、Unreal、Godot、Ren'Py、RPG Maker 等；识别不等于翻译支持。
- 译名列：Steam 官方译名 + 机翻兜底，带本地缓存与版本清理；游戏名按 Unicode 文字系统分段翻译，带垃圾结果护栏。
- 界面多语言：15 种语言 × 180+ key 内置，跟随目标语言切换。
- 端点面板：免费端点、BYOK、云端大模型、离线分类；支持禁用、自动端点（测速选最低延迟）与自定义 OpenAI 兼容端点。
- 游戏库：图标、搜索/排序、官方语言支持标注、非游戏软件过滤。
- 安装事务：备份、回滚、中断恢复、停用/恢复、配置健康检查与修复、卸载（整体还原到未安装基线）。
- 启动鸣谢与五秒倒计时；离线许可证窗口。
- 东方 thcrap 路线与 Unreal 静态准备的当前状态见兼容性矩阵。

## 五、踩过的坑（重要，别再踩）

1. **Unity 6（IL2CPP 元数据 v39）必须用 BepInEx bleeding-edge 构建**（be.788+），官方 v6.0.0-pre.2 的 Cpp2IL 只支持到 v29。
2. **XUnity.Common.dll 在 zip 的 `BepInEx/core/` 里**，不是 `plugins/`。漏了报 `FileNotFoundException`。
3. **pt-BR 必须映射为 pt** 写入 XUnity 配置（其端点不认 `pt-BR`，会静默初始化失败）。
4. **Steam API 的 `filters=name` 参数已失效**，加了返回空数据；要取全量 payload。
5. **必应免费端点**：本机会 302 到 `cn.bing.com`，必须用最终主机名拼 `ttranslatev3`；且现在必须带 `params_AbusePreventionHelper` 的 token+key 参数。
6. **Yandex 测速能过 ≠ XUnity 运行免 Key 可用**，XUnity 侧仍需 API Key。
7. 本机 `python` 命令可能是 WindowsApps 占位 stub（exit 49），脚本优先用 PowerShell。
8. **XUnity 内置 BaiduTranslate 是官方开放平台版**（要 AppId/AppSecret），不是网页免 Key 版；免 Key 内置只有 Google/V2、Bing、DeepL、Papago、彩云、CustomTranslate。
9. **XUnity CustomTranslate 只发 GET 且把响应 body 原样当译文**，返回 JSON 的接口接不了，要中间代理或自建端点插件。
10. **网页接口是消耗品**：签名与参数会随页面改版失效，需要重新核对；不要把某天的可用状态当作长期能力。
11. **游戏名机翻三原则**：非拉丁名不能进 en 管道（按 Unicode 文字系统分段）；拉丁多词名必须按短语翻不能逐词；机翻结果必须过护栏（众包库会返回「1996年总统选举」式垃圾）。
12. **WPF 数据绑定两坑**：枚举 `ObservableCollection` 时替换元素必崩（先 `.ToList()` 快照）；同引用 `Replace` 不触发 DataGrid 行重算（`RemoveAt`+`Insert` 才行）。
13. **缓存目录不能硬编码盘符**（换机即炸，已改 `AppContext.BaseDirectory`/`tools`）。
14. 不稳定 DNS（路由器首查超时）会让每个新域名首连慢十余秒——应用内做了 DNS 预热，但根治靠换系统 DNS（如 223.5.5.5 / 119.29.29.29）。
15. **「翻译完全损坏」先查 XUnity 配置是否被重置，不要先怀疑端点或 Loader**：
    - 现象：游戏内所有文本都不翻，但 `BepInEx/LogOutput.log` 显示 XUnity.AutoTranslator 已加载，构建与中继探针也都正常。
    - 根因：`AutoTranslatorConfig.ini` 被重置成出厂默认值（如 `Language=en` + `FromLanguage=ja`），目标语言缓存同时被删，于是表现为「翻译功能整体损坏」。
    - 修复：先备份损坏现场，再恢复正确的语言/源语言与端点配置，并从本机缓存备份恢复对应语言的译文。
    - 验证：必须走真实游戏链路——Steam 启动后确认缓存条数增长与新增译文；不能只看构建成功或自发自收的探针。
    - 防再踩：安装器检测到已有 BepInEx 环境会跳过，已有 ini 也默认保留，所以外部重置配置后应用不会自愈。排障顺序固定为：**先看 ini 的 `Language`/`FromLanguage` → 再看翻译缓存目录 → 再看 XUnity 加载日志 → 最后才测端点**。
16. **不要直接启动 Steam 游戏 exe 做 BepInEx 验证**：游戏触发 Steam 重启时，Steam 会继承 `DOORSTOP_INITIALIZED` / `DOORSTOP_DISABLE`，第二个游戏进程因此跳过 BepInEx，表现为全英文且没有本次 BepInEx 日志。必须先干净重启 Steam，再只经 Steam 启动；该场景已收录到内置已知错误目录，弹窗文案只用本地字典，不调用翻译端点。
17. **读取运行中的 BepInEx 日志必须允许共享写**：`File.ReadAllText` 会被写入句柄挡住，导致修复成功却报「验证失败」；统一用 `FileShare.ReadWrite` 读取，`--probe-known-issues` 已覆盖该场景。

## 六、遗留问题与下一步

按优先级：

1. **已知错误修复闭环**：检测、中文弹窗、正常关闭/干净 Steam 重启、共享日志读取和 `steam://run` 已分别验证；重复启动造成双实例无响应，安全中止已验证，仍需在稳定单实例环境完成弹窗「修复成功」闭环。
2. **「启用翻译」完整链路真机验证**：找一款没装过环境的 Unity 游戏点开关，走完下载→安装→配置→游戏内出译文。BALL x PIT 已装过环境且目前停用，不再是干净靶子，需另选。
3. **预填缓存命中验证**：手工在 `_AutoGeneratedTranslations.txt` 预填译文，重启游戏检查是否命中；记录实际等待时间，不把缓存命中描述为零延迟。
4. **BYOK 与云端端点**：六个 BYOK 端点按公开文档实现、部分零实测；云端大模型端点只做了协议模拟，需要真实 Key 与额度才能确认。
5. **网页端点签名会随网页轮换失效**：失效后需要更新客户端；不要把历史可用状态写成长期承诺。
6. **护栏盲区**：不带句读的短语级垃圾结果五条规则拦不住，靠主用端点稳定性 + 失败开放兜底。
7. **Unreal 正式启用**：仅在游戏外准备与少量菜单验证，接入正式启用入口、完整停用/恢复与画面验收仍待完成。
8. **分发状态**：未实现 Steam / Workshop 集成；平台流程与审核要求应在实际申请时另行核对，不能据旧讨论声称获准分发。

## 七、与 AI 协作的说明

本项目的开发大量使用了 AI agent。**agent 的会话上下文（resume id）绑定在各自机器上**，换机器后无法续接，用本文档作为新会话的起点即可；关键知识都落盘在 `lab/` 和本文档里，不依赖会话记忆。

Git 工作流：在功能分支上改动并提交，验证通过后再合并；提交信息写明验证方式与未验边界。
