# 验收路线图

更新：2026-10-26。最新状态和执行结果统一见 [开发进度](DEVELOPMENT-PROGRESS.md)，真实支持结论见 [兼容性矩阵](COMPATIBILITY.md)。本文件只维护执行顺序与验收门槛。

## 下一阶段：UE 静态准备优先，Godot 暂缓

两款已定位资源先完成正常翻译和恢复验证，之后按 [UE 自动适配路线图](UE-ADAPTATION-ROADMAP.md) 推进只读能力报告、处理器选择、字体/加载验证与正式启停；该路线尚未整体实现。

Unity IL2CPP / Mono 已完成两款游戏的菜单闭环，东方 ZUN 系已在 th10/th11 完成所记录页面与对话的简中验收。2026-10-25 确定先做 UE 静态 pak 覆盖路线；UE4SS 运行时路线仍属后续调研。准备流程不等于正式支持，依据见 [lab/014](../lab/014-ue-static-adapter.md)。

1. **UE 格式门槛**：pak v11/locres 合成往返、真实原包只读盘点、独立 UnrealPak 校验。原包不写入，不以自读自写通过替代游戏加载。
2. **UE 批量准备**：复用现有提供者和每游戏 PackStore；核心表先行，任务/CG 后续。遵守分段上限、熔断与失败续译，游戏目录外生成覆盖包及清单；未译值和目标独有官方值分别标记，不承诺固定时长。
3. **UE 真机门槛（验收时在场）**：确认目标目录与还原方案后放置覆盖包，窗口化静音验证加载、字体、菜单/剧情与官方译文对照，再验移除恢复与重启增量生效。此前不接正式启用按钮。
4. **Godot 后续闭环**：首款游戏先验证版本、PCK/翻译资源、字体与加载入口，再做提取→翻译→真实显示→缓存复用→停用/恢复→卸载。第二款核对复用范围，不由单款成功宣称全引擎支持。
5. **交付归档**：各阶段按实际改动更新架构导航、兼容矩阵和证据；实现改动运行相关构建及探针，文档修改仅检查结构、路径、链接和差异。

## 既有引擎的待验项

- **Unity**：补默认空缓存修复的真机重验、BALL x PIT 两次退出码 1 的定位及尚未完成的语言应用 UI 链路。两款菜单验收已完成，不重复作为新阶段起点。
- **东方 ZUN 系**：th10/th11 使用 thcrap 路线；补严格重启缓存复用及停用/恢复证据，保留 Steam 版符卡名等限制。能力探测允许的其他作品仍逐款待验，th06 PKGL 不支持。
- **悬浮窗与实验 Loader**：继续补游戏内叠加、穿透、焦点、位置记忆与多 DPI；Loader 扩大冷启动与异常覆盖后再评估正式化。均不作为 Godot 前置条件，也不标为已通过。
- **安装恢复**：已有卸载能力；继续验证冲突、部分损坏与中断恢复边界。长时间游玩由维护者手测，自动侧以短时可恢复验证为主。

所有真实游戏测试必须窗口化、小尺寸、静音，优先后台启动和指定窗口截图。不得为自动测试关闭维护者正在使用的应用、重启 Steam 或向其当前窗口注入输入；若必须前台交互而维护者仍在工作，记录精确待验步骤，等待合适的交互时段。不得将原生标志、模拟中继或缓存文件当作真实游戏画面验收。

## 长期规划（未排期，记录结论不实现）

**翻译版本管理**（2026-10-24 讨论定案，暂缓开发）：

- 远景操作：下载推荐翻译顶替本地并可找回、翻译包对比、翻译合并。届时涉及社区包分发/签名/防恶意包，另需专项设计。
- 存储结论：**不引入 git**。版本单元是字符串级翻译（PackStore 逐条 KV）与补丁状态，不是文件树；diff/merge 的正确粒度是字符串级三方合并（本地改取本地、远端改取远端、都改冲突给用户挑），git 的行级文本 diff/merge 用不上，原生 libgit2 只增加故障面。参照路径：thcrap 补丁中心（自研 patch 栈，非 git）。
- 落地形态：逐字符串存储（带来源标记：机翻/社区包/用户手改）+ 快照栈（回收站语义，找回 7 天内最多 3 份）+ 字符串级三方合并。存储层以接口隔离，若将来出现任意长历史/跨设备同步需求，接口后换实现仍是低成本。
- 前置依赖：适配器产物与还原边界稳定、社区包格式定义。东方现走 thcrap 与字体渲染路线，不再以旧静态字形表方案为前置。当前卸载/修复已覆盖"还原到基线"，快照/找回短期内收益有限，故不开发。
