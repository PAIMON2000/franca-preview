# UE 自动适配路线图

日期：2026-10-26。本文描述未来工程路线，不表示已交付。当前执行结果统一见 [开发进度](DEVELOPMENT-PROGRESS.md)，逐游戏结论见 [兼容矩阵](COMPATIBILITY.md)。

## 本轮范围与依据

先稳定《逸剑风云决》和《歧路旅人 2》的已定位文本翻译及可恢复覆盖，不在本轮同时开放所有 UE 游戏的正式启用按钮。

两款已暴露三类差异：标准 locres、自定义 cooked DataTable、文字做在纹理中。pak 可读取不等于文本可修改；工具校验成功不等于目标游戏可加载（逸剑的压缩覆盖曾失败）。独有标记只用于首次诊断，正常翻译产物不带 Franca 提示。不能从两款成功推算 UE 总体支持比例。

现有可复用基础：pak v11 读写与校验、locres 处理、实例隔离的翻译缓存/熔断/分段续译、安装事务设计。本轮为八方的已验证数据表结构补充严格读写及批译入口。尚未完成自动发现、通用字体替换、UE 安装 UI、任意数据表/图片处理；这些不能在界面显示为已支持。

## 阶段一：只读能力报告

输入明确的游戏目录，输出结构化报告：安装版本与文件指纹、容器版本、索引是否可读、加密/签名迹象、文本资源候选、语言槽位、已知覆盖冲突、每项判断的证据与失败原因。

先识别已实现的 pak v11 与 locres；自定义表须按结构检查，文件名只是候选线索。扫描设文件数、大小和解析时间限制，拒绝越界、未知序列化历史及目录跳转。不联网、不写游戏目录、不因“UE”标签自动安装。

完成门槛：两款真包及合成的未知/损坏包均产生可解释报告；“无法解析”“没有找到文本”“文本不完整”明确区分。未来再实现 IoStore 或其他 pak 版本，不把它们默认标为兼容。

## 阶段二：处理器选择与统一文本模型

处理器声明格式版本、结构指纹、支持字段、读写条件和输出范围。统一条目至少包含资源路径、行/命名空间/键、源内容哈希、语言槽位、原始格式标记。兼容性按资源报告，同一游戏允许多种处理器并存。

依次实现 locres、已验证的 FText DataTable 结构；字符串表和其他数据表按证据新增。必须通过空修改逐字节一致、修改后重新解析、未选字段字节不变、未知结构拒绝。图片菜单独立报告，不能通过“未发现字符串”误称无需翻译。

完成门槛：以两款的现有适配为回归，加至少一个不同项目确认同一处理器可复用。新增版本不满足指纹时明确降级，不猜测偏移。

## 阶段三：字体与小型加载验证

静态检查目标译文所需字符、实际字体资源及引用关系；字体格式可解析时报告缺字集合。无法解析或无法确认实际使用字体时报告未知，不宣称字体健康。

针对未验游戏先生成少量、易恢复的测试覆盖包；用独有标记和当前版本指纹区分官方译文。可用日志确认挂载/错误，用户或获得授权的画面检查确认显示；真实画面确认后才能把该版本标为已验证。字体替换须另管来源、许可、引用、回退和备份。

### 字体来源与分发（2026-10-30 定案）

真机证据（见 [真机验证记录](../tests/2026-10-30-octopath2-live.md)）：目标语言没有官方槽位时，游戏自带字体可能缺字形（本作 `.ufont` 为裸 TTF、`KS_*` 为子集字体，日语 ー/続/設 不渲染）。字体支持由 Franca 自管，不走官方其他语言槽位。

- **来源**：自带 OFL 开源字体（默认 Noto Sans CJK 一套 + Noto Sans 拉丁系），许可证文本随 `LICENSES/` 释放；不使用厂商系统字体做默认（可用性与许可不可控），仅保留"玩家手动指定本机字体"作为可选增强。
- **分发三层**：核心字体嵌入独立 EXE、首启随 ThirdParty 释放（零下载）；其余字体作为 GitHub Release 资产按需下载；镜像（jsDelivr 等）仅作加速回退，正确性以 SHA-256 哈希为准，支持用户自定义镜像。
- **注入**：准备阶段把字体资产注入游戏外覆盖包（同路径替换或挂 Font 资产回退链），原 pak 不动。

完成门槛：显示、假名字形、变量/富文本、换行、长文溢出分别记录；启动存活不替代验收。正式译文移除诊断标记。

## 阶段四：准备、安装、停用与恢复

准备始终在游戏外；缺译和失败明确记录，未完成产物不进入正式安装。沿用 AppTranslator、PackStore、分段限制、请求快照和续译，按游戏与目标语言隔离；网络目的地及内容范围遵循用户授权。

UE 安装接入事务服务：游戏停止后核对基线和冲突，先记录意图与备份，再原子替换自有覆盖包；完成清单记录源包指纹、目标语言/槽位、处理器版本、每个自有文件哈希。中断先恢复，不能显示就绪。停用仅撤回哈希匹配的自有文件，保留其他模组、存档和原包；第三方修改、游戏更新或未知文件均转为冲突提示。

完成门槛：临时夹具覆盖失败/取消/中断/外部冲突；两款分别完成正常显示→停用重启官方文本→恢复重启译文→重复操作幂等。游戏更新后旧证据失效，重新检查。

## 阶段五：正式入口与扩大样本

页面只展示简明状态和服务调用：可准备、待验证、可启用、部分覆盖、暂不支持、需要恢复。提供翻译范围与缺项，不能把文件准备完毕等同完整游戏支持。

先接两款已验版本，再选不同 UE4 版本及 UE5/不同容器逐款补证据。分别统计已识别、可解析、可准备、已实际显示、已恢复的样本数；没有代表性样本和分母时，不发布总体兼容百分比。

运行时新文本捕获、游戏内热更新、未知图片自动重绘和受保护容器属独立路线，暂不承诺排期。UE4SS 等方案须另行评估，不由静态处理器自动兜底。

## 代码边界与交接

格式编解码留在 `Services/UePak`；准备和能力分析属于服务，页面不解析包、不直接联网或写游戏。正式启停由 `GameTranslationService` 调度，安装器接收明确产物与目标，不依赖 MainWindow、不自行启动中继。新增边界先同步 architecture.json，再更新系统地图和蓝图。

每阶段独立可交付；先完成两款实际闭环，再推进下一阶段。日期证据仅保存方法、摘要、计数和哈希；原游戏资源、机翻缓存、备份、完整日志及凭证保留本机，不上传 GitHub。
