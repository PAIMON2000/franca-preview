# 2026-10-23 Loader 构建与隔离验证

用户本轮明确要求自研 Loader 与游戏翻译验收都完成；此前「先只做后台检查，交互测试留待空闲」的限制继续有效。此记录只覆盖无游戏、无输入的原生与托管验证，不宣称真机兼容。

## 实现

新增 PowerShell 构建/测试入口，自动定位现有 VS2022 C++ 工具链，从本机 System32 WinHTTP 生成 70 个命名/序号转发导出和保留 x64 参数的 MASM 桩。补全来源许可、构建版本与输入哈希。

改造原实验代码：执行 enabled / 显式实验开关和继承环境停用；使用有界 Unicode 路径和 CoreCLR UTF-8 路径；DllMain 中不再加载系统 DLL、执行日志 I/O 或初始化托管运行时；工作线程逐阶段输出错误。系统库必须通过 GetSystemDirectory 拼绝对路径：首次夹具揭露仅传 winhttp.dll + SYSTEM32 标志仍可能命中代理自身并递归，修正后通过。

## 验证

- MSVC 14.44.35207、Windows SDK 10.0.22621.0，Windows x64。
- 同源码/工具链/SDK/系统 DLL 输入，两处输出目录构建 DLL 的 SHA-256 相同：`3BB50CB7E54FB53B87299653DF4AA598745642ED785EED2CDCA4B26B4460DC52`。不同系统输入不作相同产物承诺。
- 编译按 /W4 /WX；链接保留两个 COM 导出的系统序号，存在两项 LNK4222 建议，不能称原生零警告。
- 16 个隔离进程用例：配置缺失、禁用、未选择实验、继承停用/初始化标志、目标缺失、corlib 缺失、CoreCLR 缺失、导出缺失、初始化失败、委托失败、入口异常、成功、中文路径、真实 CoreCLR、真实 CoreCLR 中文路径。
- 每个进程先检查转发桩的 x64 展开表存在，再调用真正的系统 WinHTTP Open / Connect / OpenRequest / CloseHandle，覆盖 5/7 参数转发，但不 SendRequest，因此没有网络请求。
- 真正的 .NET 9 CoreCLR 初始化、创建委托和调用托管 Doorstop.Entrypoint.Start 后，探针检查 managed-entrypoint.ok 标记；没有把模拟 CoreCLR 当作真实运行时验证。
- 原始 stdout、阶段日志、build-info.json 位于 `tests/artifacts/loader/`；运行命令 `pwsh -File src/Loader/test.ps1`。

## 未验收边界

没有启动真实游戏，没有替换 BALL x PIT / Potion Craft 的 DLL 或配置。Loader 从工作线程直接引导与真实 Unity/il2cpp_init 的时序尚未验证，不能视作正式发布实现；不支持 x86/Mono 注入、运行中卸载或跨 Windows 导出集分发。

原生隔离测试与先前桌面 254 项检查是不同层次。待用户空闲后，先验证上游加载链，再在备份下单独验证自研代理，按窗口化、小尺寸、静音方式记录画面、BepInEx/XUnity 日志、缓存复用及恢复结果。真实 Unity 引导失败需修复初始化时序，不能仅把返回码改成成功。
